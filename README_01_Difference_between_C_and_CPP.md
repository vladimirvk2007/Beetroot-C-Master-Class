## 1. Різниця між C і C++

### Чому це важливо в embedded

У вбудованих системах ми працюємо з обмеженими ресурсами: пам'ять, частота CPU, енергоспоживання, час реакції. Вибір між C і C++ впливає на:

- читабельність і підтримку коду;
- швидкість розробки;
- ризик помилок у runtime;
- контроль над пам'яттю та продуктивністю.

### Коротке порівняння

| Критерій | C | C++ |
|---|---|---|
| Парадигма | Процедурна | Процедурна + ООП + generic |
| Абстракції | Мінімальні | Класи, шаблони, RAII, constexpr |
| Повторне використання коду | Через функції/макроси | Через шаблони, класи, namespaces |
| Безпека типів | Базова | Вища (перевантаження, шаблони, strong typing) |
| Керування ресурсами | Ручне | RAII дозволяє автоматизувати звільнення ресурсів |
| Вартість помилок | Часто вище через ручне керування | Менша за умови правильних практик |
| Поріг входу | Нижчий | Вищий |

### C в embedded: сильні сторони

- Простий бінарний інтерфейс і прогнозована генерація коду.
- Дуже легка інтеграція зі старими toolchain і HAL.
- Менше "магії" мови, простіше аналізувати асемблер.

Коли C доречний:

- low-level startup code;
- very constrained MCU;
- legacy кодова база повністю на C;
- строгі вимоги до сертифікації зі зрілими C-процесами.

### C++ в embedded: сильні сторони

- Краща модульність через класи та простори імен.
- RAII прибирає частину витоків ресурсів і проблем cleanup.
- Шаблони дозволяють zero-cost абстракції (без runtime overhead за правильного використання).
- constexpr і типобезпечні обгортки зменшують кількість помилок.

Коли C++ доречний:

- середні/великі проєкти з довгим життєвим циклом;
- командна розробка, де важлива підтримуваність;
- потреба в compile-time конфігурації (templates, constexpr);
- використання бібліотек на кшталт ETL.

### Важливий міф: C++ = "важко" для MCU

C++ не обов'язково означає більший код або повільніше виконання.

Проблеми зазвичай виникають не через саму мову, а через неконтрольоване використання:

- dynamic allocation без політики;
- винятки і RTTI (Run-Time Type Identification) там, де вони не потрібні;
- надмірно важкі частини стандартної бібліотеки для конкретного target.

У практичному embedded C++ часто використовують профіль:

- без heap або з жорсткою політикою heap;
- без exceptions;
- без RTTI;
- з ETL або обмеженим піднабором STL.

### Приклад стилю C

```c
#include <stdint.h>

typedef struct {
    uint16_t value;
} adc_t;

static void adc_init(adc_t* adc) {
    adc->value = 0;
}

static uint16_t adc_read(const adc_t* adc) {
    return adc->value;
}
```

### Приклад стилю C++

```cpp
#include <cstdint>

class Adc {
public:
    Adc() : value_(0) {}

    uint16_t read() const {
        return value_;
    }

private:
    uint16_t value_;
};
```

### Практичний висновок

- C дає максимальну простоту й контроль "в лоб".
- C++ дає кращі інструменти для масштабу, безпеки типів і підтримки.
- Для сучасного embedded часто працює змішана стратегія:
  - very low-level шар: C або C-like C++;
  - бізнес-логіка і модулі: C++ (з обмеженнями профілю).
