# Питання 4. Макроси і constexpr

## Що це таке

### Макроси (`#define`)

Макрос це текстова підстановка на етапі препроцесора, ще до компіляції.

Приклади:

```c
#define LED_PIN 13
#define SQUARE(x) ((x) * (x))
```

Особливість: препроцесор не "розуміє" типи, він просто замінює текст.

### `constexpr` (C++)

`constexpr` означає, що значення або функція можуть бути обчислені на етапі компіляції.

Приклади:

```cpp
constexpr int LedPin = 13;

constexpr int square(int x) {
    return x * x;
}
```

Особливість: працює в системі типів C++, перевіряється компілятором і безпечніше за макроси.

## Ключова різниця

1. Етап обробки
- Макрос: препроцесор (текст).
- `constexpr`: компілятор C++ (типобезпечні сутності).

2. Типобезпека
- Макрос: немає типів.
- `constexpr`: повна перевірка типів.

3. Відлагодження
- Макрос: важче дебажити (після підстановки вихідний вигляд змінюється).
- `constexpr`: звичайні змінні/функції, легше читати й дебажити.

4. Побічні ефекти
- Макрос-функція може обчислити аргумент кілька разів.
- `constexpr` функція поводиться як звичайна функція.

## Типова помилка з макросом

```c
#define SQUARE(x) x * x

int y = SQUARE(1 + 2); // дасть 1 + 2 * 1 + 2 = 5, а не 9
```

Навіть з дужками є інші ризики:

```c
#define INC(x) ((x) + 1)
int i = 0;
int y = INC(i++); // побічні ефекти в аргументах небезпечні
```

Безпечніша альтернатива в C++:

```cpp
constexpr int square(int x) {
    return x * x;
}
```

## Коли макроси все ще доречні

У C і embedded макроси залишаються корисними для:

- include guards;
- умовної компіляції (`#if`, `#ifdef`);
- platform flags (`DEBUG`, `STM32F4`, тощо);
- низькорівневих бітових масок і адрес регістрів (особливо в C-коді).

Приклад:

```c
#define BIT(n) (1u << (n))
#define UART_SR_TXE BIT(7)
```

## Коли краще `constexpr`

У C++ `constexpr` краще для:

- констант замість `#define`;
- обчислень на етапі компіляції;
- таблиць і параметрів конфігурації;
- helper-функцій без runtime overhead.

Приклад:

```cpp
constexpr uint32_t baudrate(uint32_t pclk, uint32_t div) {
    return pclk / div;
}

constexpr uint32_t UartBaud = baudrate(16000000u, 16u);
```

## Практичні рекомендації для embedded

1. У C++ віддавайте перевагу `constexpr` і `const` замість `#define` для констант.
2. Лишайте макроси для conditional compilation та platform switches.
3. Уникайте "макросів-функцій" там, де можна написати `constexpr`/`inline` функцію.
4. Якщо макрос неминучий, завжди:
- беріть аргументи і весь вираз у дужки;
- не передавайте вирази з побічними ефектами (`i++`, `--j`).

## Порівняння на одному прикладі

### Макрос (C/C++)

```c
#define MAX_BUFFER 128
```

### C++ стиль

```cpp
constexpr size_t MaxBuffer = 128;
```

Що краще у C++:

- видно тип (`size_t`);
- кращий scope-контроль;
- легше рефакторити;
- менше шансів на помилки підстановки.

## Висновок

- Макроси потрібні, але їх роль в C++ має бути мінімальною.
- Для обчислень і констант у C++ краще використовувати `constexpr`.
- У сучасному embedded C++ правило просте: "макроси для конфігурації, `constexpr` для логіки і значень".
