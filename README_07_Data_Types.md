# Питання 7. Типи даних (C/C++)

## Чому це критично в embedded

У вбудованих системах тип даних напряму впливає на:

- використання RAM/Flash;
- швидкість виконання;
- коректність арифметики;
- сумісність з периферією та протоколами.

Неправильно обраний тип часто дає приховані баги: переповнення, помилки знаковості, втрату точності.

## Базові категорії типів

1. Цілочисельні
- `char`, `short`, `int`, `long`, `long long`
- signed/unsigned варіанти

2. Логічні
- C: `_Bool` (через `stdbool.h` як `bool`)
- C++: `bool`

3. Символьні
- `char`, `wchar_t` (у C++ також `char16_t`, `char32_t`)

4. Дійсні (floating point)
- `float`, `double`, `long double`

5. Спеціальні/похідні
- `enum`, `struct`, `union`, pointers, arrays

## Чому не варто покладатися на "звичайний int"

Розмір `int` залежить від платформи/ABI. На різних MCU або host-системах він може відрізнятись.

Тому в embedded практиці зазвичай використовують fixed-width типи з:

- C: `stdint.h`
- C++: `cstdint`

Приклади:

- `uint8_t`, `int8_t`
- `uint16_t`, `int16_t`
- `uint32_t`, `int32_t`
- `uint64_t`, `int64_t`

## Рекомендовані типи для embedded

1. Для регістрів, пакетів, протоколів
- `uint8_t/uint16_t/uint32_t`

2. Для лічильників і розмірів буферів
- `size_t` (коли це саме "розмір у байтах/елементах")

3. Для різниці індексів
- `ptrdiff_t` або signed fixed-width тип

4. Для адрес/цілих, що вміщують pointer
- `uintptr_t`, `intptr_t`

5. Для булевих прапорців
- `bool`

## Signed vs Unsigned

### Загальне правило

- Використовуйте `unsigned` для бітових масок і полів, де від'ємні значення не мають сенсу.
- Використовуйте `signed`, якщо математично можливі від'ємні значення.

### Типова пастка

Порівняння signed і unsigned може дати неочікуваний результат через неявні перетворення типів.

```cpp
int a = -1;
unsigned int b = 1;
if (a < b) {
    // Може НЕ виконатись так, як очікуєте
}
```

## Переповнення

1. Unsigned integer overflow
- Визначена поведінка: арифметика по модулю $2^N$.

2. Signed integer overflow
- Невизначена поведінка (UB) у C/C++.

Практика:

- перевіряйте межі перед додаванням/множенням;
- використовуйте ширший тип для проміжних обчислень;
- додавайте assert/check у критичних місцях.

## Floating point в embedded

- `float` зазвичай 32-бітний.
- `double` на частині MCU може бути таким же, як `float`, або 64-бітним.
- Операції з float можуть бути дорогими без FPU.

Рекомендації:

1. Для жорсткого real-time розглядайте fixed-point арифметику.
2. Мінімізуйте float у ISR.
3. Контролюйте вивід float (`printf`) через вплив на розмір бінарника.

## C vs C++ у контексті типів

1. C++ дає сильніші інструменти типобезпеки
- `enum class`
- `constexpr`
- шаблони (`std::is_integral`, `std::numeric_limits`)

2. C простіший, але потребує більше дисципліни
- ручний контроль перетворень;
- акуратність у macro/typedef підходах.

## Корисні практики

1. Явні суфікси літералів

```cpp
uint32_t t = 1000u;
uint64_t mask = 1ull << 40;
```

2. Явні касти тільки за потреби

```cpp
uint16_t lo = static_cast<uint16_t>(value & 0xFFFFu);
```

3. Не використовуйте `char` як байтовий контейнер для арифметики
- краще `uint8_t`.

4. Для API протоколів фіксуйте точні типи у header
- це зменшує platform-dependent помилки.

## Мінімальний приклад

```cpp
#include <cstdint>

struct SensorFrame {
    uint16_t id;
    int16_t temperature_c_x10;
    uint32_t timestamp_ms;
    uint8_t status;
};
```

Перевага: формат кадру стабільний і передбачуваний на різних платформах.

## Висновок

- В embedded краще мислити не "зручними" типами, а "точними" типами.
- Fixed-width типи (`uint32_t`, `int16_t`...) мають бути стандартом у протоколах, драйверах і критичній логіці.
- Типобезпека в C++ допомагає знизити кількість багів, але дисципліна потрібна в обох мовах.
