# Питання 8. Приведення типів (кастінг) в C і C++

## Що таке кастінг

Приведення типів (casting) це перетворення значення одного типу в інший.

У low-level та embedded коді це трапляється часто:

- робота з регістрами;
- парсинг пакетів;
- перетворення ширини типів;
- робота з вказівниками та адресами.

Неправильний кастінг легко дає баги: втрату даних і неочікувані результати.

## Кастінг у C

### Явне приведення (C-style cast)

```c
int a = 300;
uint8_t b = (uint8_t)a; // обрізання до 8 біт
```

Особливість C-style cast:

- короткий запис;
- майже не видно наміру;
- може приховувати небезпечні перетворення.

## Кастінг у C++

У C++ для базового рівня достатньо знати один головний варіант: `static_cast`.

### 1. static_cast

Для безпечних, компіляторно-перевірюваних перетворень між сумісними типами.

```cpp
int a = 300;
uint8_t b = static_cast<uint8_t>(a);
```

Інші типи кастів у C++ (наприклад, `const_cast`, `reinterpret_cast`, `dynamic_cast`) для стартового рівня поки не розглядаємо.

## Implicit vs explicit conversion

### Неявне (implicit)

Компілятор сам перетворює типи:

```cpp
uint32_t x = 10;
uint64_t y = x; // розширення
```

### Явне (explicit)

Робите перетворення самі:

```cpp
uint64_t big = 1000;
uint16_t small = static_cast<uint16_t>(big);
```

Практика: для звуження типу (narrowing) краще явний каст + перевірка меж.

## Ключові ризики

1. Narrowing conversion
- Втрата старших бітів або точності.

2. Signed/unsigned conversion
- Несподівані значення після перетворення.

3. Надмірні перетворення
- Велика кількість кастів часто сигналізує про проблему дизайну типів.

## C vs C++: коротко

1. C
- Переважно C-style cast `(type)expr`.
- Менше семантики, більше відповідальності на розробнику.

2. C++
- Для більшості навчальних і прикладних задач використовуйте `static_cast`.
- Код читабельніший і легше проходить code review.

## Embedded-практики (рекомендовано)

1. У C++ уникайте C-style cast у новому коді.
2. Для числових перетворень використовуйте `static_cast`.
3. Перевіряйте межі перед narrowing:

```cpp
uint32_t v = read_value();
if (v <= 0xFFFFu) {
    uint16_t s = static_cast<uint16_t>(v);
    use_short(s);
}
```

4. Робіть перетворення явними, щоб одразу було видно намір у коді.

## Приклади безпечнішого підходу

### C: контрольований каст

```c
#include <stdint.h>

uint16_t to_u16_checked(uint32_t v) {
    if (v > 0xFFFFu) {
        return 0xFFFFu;
    }
    return (uint16_t)v;
}
```

### C++: явний намір

```cpp
#include <cstdint>

uint16_t to_u16_checked(uint32_t v) {
    if (v > 0xFFFFu) {
        return 0xFFFFu;
    }
    return static_cast<uint16_t>(v);
}
```

## Висновок

- Кастінг у embedded неминучий, але має бути контрольованим.
- C-style cast зручний, проте менш безпечний і менш прозорий.
- У C++ на старті достатньо опанувати `static_cast` і звичку перевіряти межі значень.
