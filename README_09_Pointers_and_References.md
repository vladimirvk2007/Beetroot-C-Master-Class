# Питання 9. Вказівник і посилання

## 1. Що це таке

### Вказівник (pointer)

Вказівник це змінна, яка зберігає адресу іншого об'єкта в пам'яті.

- Тип вказівника визначає, як інтерпретувати дані за цією адресою.
- Вказівник може бути `nullptr`/`NULL`.
- Вказівник можна перенаправити на інший об'єкт.

Приклад:

```cpp
int x = 10;
int* p = &x;   // p зберігає адресу x
```

### Посилання (reference, C++)

Посилання це альтернативне ім'я для вже існуючого об'єкта.

- Має бути ініціалізоване одразу.
- Не може бути "порожнім" у нормальній моделі використання.
- Не можна "переприв'язати" до іншого об'єкта після ініціалізації.

Приклад:

```cpp
int x = 10;
int& r = x;    // r це інше ім'я x
```

---

## 2. Синтаксис і базові операції

### Для вказівників

1. Отримати адресу: `&obj`
2. Розіменувати: `*ptr`
3. Доступ до поля через вказівник: `ptr->field`

```cpp
struct S { int value; };
S s{42};
S* ps = &s;
int a = (*ps).value;
int b = ps->value;
```

### Для посилань

- Використовуються як звичайні змінні, без `*` і `->`.

```cpp
int x = 5;
int& rx = x;
rx = 7; // змінює x
```

---

## 3. Ключова різниця: pointer vs reference

1. Може бути null
- Вказівник: так (`nullptr`).
- Посилання: ні (у нормальному C++ коді).

2. Може змінювати "ціль"
- Вказівник: так (`p = &other`).
- Посилання: ні (після ініціалізації завжди той самий об'єкт).

3. Синтаксис використання
- Вказівник: `*p`, `p->`.
- Посилання: як звичайна змінна.

4. В інтерфейсах
- Вказівник часто сигналізує "може бути відсутнє значення".
- Посилання частіше означає "об'єкт обов'язково існує".

---

## 4. C і C++: відмінності

### У C

- Є лише вказівники.
- Імітація "посилання" робиться через pointer-параметри:

```c
void inc(int* v) {
    (*v)++;
}
```

### У C++

- Є і вказівники, і посилання.
- Часто використовують посилання для API, де null не очікується:

```cpp
void inc(int& v) {
    v++;
}
```

---

## 5. Вказівники і пам'ять

### Області пам'яті

1. Stack
- Локальні змінні функції.

2. Static/Global
- Глобальні й static-змінні.

3. Heap
- Динамічні виділення (`new/delete`, `malloc/free`).

Для embedded часто політика така:

- мінімізувати або забороняти heap;
- працювати зі статичною/автоматичною пам'яттю;
- уникати фрагментації.

---

## 6. null pointers і безпека

### Чому важливо

Розіменування null-вказівника -> UB/HardFault.

```cpp
int* p = nullptr;
// int x = *p; // помилка часу виконання
```

### Практика

1. Ініціалізуйте вказівники одразу.
2. Перевіряйте `p != nullptr` перед розіменуванням.
3. Після звільнення ресурсу обнуляйте вказівник (де це доречно).

---

## 7. const і вказівники/посилання

### Варіанти для pointer

```cpp
int x = 1;
int y = 2;

const int* p1 = &x; // не можна змінювати *p1, можна змінити p1
int* const p2 = &x; // можна змінювати *p2, не можна змінити p2
const int* const p3 = &x; // не можна ні те, ні інше
```

### Для reference

```cpp
int x = 1;
const int& r = x; // через r не можна змінювати x
```

---

## 8. Передача параметрів у функції

### 1. За значенням

```cpp
void f(int v) { v++; }
```

- Копія, оригінал не змінюється.

### 2. За вказівником

```cpp
void f(int* v) {
    if (v) { (*v)++; }
}
```

- Можна передати "нічого" (`nullptr`).

### 3. За посиланням (C++)

```cpp
void f(int& v) { v++; }
```

- Об'єкт обов'язковий, синтаксис чистіший.

### 4. За const reference (C++)

```cpp
void print(const MyType& t);
```

- Без копії, без модифікації.

Практичне правило:

1. Маленькі типи (`int`, `uint32_t`) -> часто by value.
2. Великі об'єкти -> `const T&`.
3. Опціональний параметр -> pointer.
4. Обов'язкова модифікація без null -> `T&`.

---

## 9. Pointer arithmetic

### Суть

`p + 1` зміщає вказівник на `sizeof(*p)` байт.

```cpp
int arr[3] = {10, 20, 30};
int* p = arr;
// *p == 10
// *(p + 1) == 20
```

### Ризики

- Вихід за межі масиву -> UB.
- Неправильні обчислення меж у циклах.

Для навчання краще спочатку використовувати індекси і range-based цикли.

---

## 10. Масиви і вказівники

- Ім'я масиву в більшості виразів деградує до вказівника на перший елемент.

```cpp
int arr[5];
int* p = arr; // еквівалентно &arr[0]
```

Але це не одне і те саме:

- `sizeof(arr)` -> розмір усього масиву.
- `sizeof(p)` -> розмір вказівника.

---

## 11. Вказівник на вказівник

```cpp
int x = 5;
int* p = &x;
int** pp = &p;
```

Використовується для:

- модифікації вказівника у функції;
- таблиць вказівників;
- окремих C API.

---

## 12. Dangling pointers

Dangling pointer це вказівник на невалідну пам'ять.

Типовий випадок:

```cpp
int* bad_ptr() {
    int x = 10;
    return &x; // повертає адресу локальної змінної
}
```

Після виходу з функції `x` знищений.

Практика:

- не повертайте адреси локальних об'єктів;
- контролюйте час життя об'єкта;
- у C++ використовуйте RAII-контейнери/об'єкти власності.

---

## 13. Динамічна пам'ять (коротко)

### C

```c
int* p = malloc(sizeof(int) * 10);
if (p) {
    free(p);
}
```

### C++

```cpp
int* p = new int[10];
delete[] p;
```

Для embedded-початківців краще:

- уникати `malloc/new` у базових прикладах;
- використовувати статичні буфери або fixed-capacity контейнери (ETL).

---

## 14. Посилання в C++: додатково

### Lvalue reference

```cpp
int x = 10;
int& r = x;
```

### Const reference до тимчасового об'єкта

```cpp
const int& r = 42; // дозволено
```

Це важливо для ефективної передачі параметрів.

---

## 15. Типові помилки

1. Забули ініціалізувати pointer.
2. Розіменували `nullptr`.
3. Вийшли за межі масиву через pointer arithmetic.
4. Повернули адресу локальної змінної.
5. Плутають `const int*` та `int* const`.
6. Не перевірили pointer-параметр на null.
7. Зробили зайвий каст замість виправлення типів у дизайні.

---

## 16. Embedded-рекомендації

1. За замовчуванням: прості типи + чіткі межі масивів.
2. Для API: використовуйте `const` максимально широко.
3. Для необов'язкових аргументів у C++ використовуйте pointer (`nullptr` як "нема").
4. Для обов'язкових об'єктів у C++ використовуйте reference.
5. У критичних місцях мінімізуйте складну pointer-арифметику.
6. Документуйте ownership: хто створює/хто звільняє ресурс.
7. В початкових курсах обмежуйте dynamic allocation.

---

## 17. Міні-шпаргалка: що обирати

1. Потрібно змінити значення і null не допускається (C++) -> `T&`.
2. Параметр опціональний -> `T*`.
3. Потрібно читати великий об'єкт без копії -> `const T&`.
4. Потрібно працювати з масивом у C API -> `T*` + довжина.
5. Потрібна ясність "є/немає об'єкта" -> pointer.

---

## 18. Приклади для заняття

### C: swap через pointers

```c
void swap_int(int* a, int* b) {
    if (!a || !b) {
        return;
    }
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
```

### C++: swap через references

```cpp
void swap_int(int& a, int& b) {
    int tmp = a;
    a = b;
    b = tmp;
}
```

### C++: API з обов'язковим і опціональним параметрами

```cpp
struct Config {
    int baudrate;
};

void init_uart(const Config& cfg, int* error_code) {
    if (cfg.baudrate <= 0) {
        if (error_code) {
            *error_code = 1;
        }
        return;
    }
    if (error_code) {
        *error_code = 0;
    }
}
```

---

## 19. Висновок

- Вказівник це "адреса, яка може бути порожньою і може змінювати ціль".
- Посилання це "обов'язковий псевдонім існуючого об'єкта".
- У C працюємо переважно через pointers.
- У C++ зазвичай: `const T&` для читання, `T&` для обов'язкової модифікації, `T*` для опціональності.
- Для embedded головне: контроль меж, `const`-коректність, зрозумілий ownership і мінімум небезпечної pointer-арифметики.
