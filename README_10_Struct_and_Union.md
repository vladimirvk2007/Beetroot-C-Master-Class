# Питання 10. Структури (struct) та Об'єднання (union)

## 1. Навіщо це потрібно в embedded

У вбудованих системах ми часто працюємо з:

- пакетами даних;
- регістрами периферії;
- компактним зберіганням стану;
- протоколами обміну байтами.

`struct` і `union` це базові інструменти для опису таких даних на рівні пам'яті.

---

## 2. Що таке struct

`struct` об'єднує кілька полів в один логічний тип.

Кожне поле має:

- власний тип;
- власний офсет у пам'яті;
- одночасно існує разом з іншими полями.

### Приклад (C/C++)

```c
struct SensorData {
    uint16_t id;
    int16_t temperature_x10;
    uint32_t timestamp_ms;
};
```

Тут усі поля незалежно зберігаються в одному об'єкті `SensorData`.

---

## 3. Що таке union

`union` це тип, у якому всі поля накладаються на одну і ту ж область пам'яті.

- У кожен момент коректно використовувати лише те поле, яке було останнім записане (залежно від правил aliasing і активного члена).
- Розмір union дорівнює розміру найбільшого поля (з урахуванням вирівнювання).

### Приклад

```c
union Value {
    uint32_t u32;
    float f32;
    uint8_t bytes[4];
};
```

Усі `u32`, `f32`, `bytes` ділять одну й ту ж пам'ять.

---

## 4. Головна різниця struct vs union

1. Пам'ять
- `struct`: пам'ять для всіх полів окремо.
- `union`: одна спільна пам'ять для всіх полів.

2. Використання
- `struct`: коли потрібні всі поля одночасно.
- `union`: коли потрібне одне з кількох представлень того самого буфера.

3. Ризик помилок
- `struct`: нижчий.
- `union`: вищий, бо легко прочитати не те представлення.

---

## 5. Розмір, вирівнювання і padding

Компілятор може додавати padding між полями `struct` для вирівнювання.

### Приклад

```c
struct A {
    uint8_t a;
    uint32_t b;
};
```

Логічно поля це 1 + 4 = 5 байт, але фактичний `sizeof(A)` часто 8 через padding.

Чому це важливо:

- для мережевих пакетів;
- для протоколів;
- для memory-mapped структур.

Перевірка:

```c
_Static_assert(sizeof(struct A) == 8, "Unexpected size"); // C11
```

```cpp
static_assert(sizeof(A) == 8, "Unexpected size"); // C++
```

---

## 6. struct в C і C++

### У C

- Пишемо `struct TypeName`.
- Часто додають `typedef`, щоб не писати `struct` кожного разу.

```c
typedef struct {
    uint16_t id;
    uint16_t value;
} AdcSample;
```

### У C++

- `struct` і `class` дуже схожі.
- Різниця за замовчуванням:
  - `struct` -> `public`
  - `class` -> `private`

```cpp
struct AdcSample {
    uint16_t id;
    uint16_t value;
};
```

---

## 7. union в C і C++: нюанси

`union` корисний, але потребує дисципліни.

Безпечний початковий підхід:

1. Використовувати union переважно з простими POD-типами (`uint32_t`, масив байтів).
2. Документувати, яке поле "активне".
3. Не змішувати складні типи без чіткого контролю часу життя.

---

## 8. Практичні embedded-сценарії

### 1. Структура пакета

```c
typedef struct {
    uint8_t header;
    uint8_t length;
    uint8_t payload[8];
    uint8_t crc;
} Frame;
```

### 2. Представлення слова і байтів (union)

```c
typedef union {
    uint32_t word;
    uint8_t bytes[4];
} WordBytes;
```

Це зручно для low-level задач, але враховуйте endianness.

### 3. Стан із взаємовиключними полями

```c
typedef struct {
    uint8_t mode;
    union {
        uint16_t pwm;
        uint16_t adc;
    } data;
} DeviceState;
```

`mode` визначає, яке поле union валідне.

---

## 9. Endianness і union

Навіть якщо union дозволяє дивитися на байти числа, порядок байтів залежить від архітектури:

- little-endian;
- big-endian.

Тому для протоколів краще:

- явно пакувати/розпаковувати байти через зсуви;
- не покладатися на "внутрішнє" представлення без перевірки.

---

## 10. Bit fields (коротко)

У `struct` можна використовувати бітові поля:

```c
struct Flags {
    uint8_t ready : 1;
    uint8_t error : 1;
    uint8_t mode  : 2;
    uint8_t rsvd  : 4;
};
```

Але для embedded-протоколів це часто ризиковано через implementation-defined деталі (порядок бітів/пакування).

Практика:

- для переносимості частіше використовують маски й зсуви (`&`, `|`, `<<`, `>>`).

---

## 11. Типові помилки

1. Ігнорують padding у struct при серіалізації.
2. Читають "неактивне" поле union.
3. Плутають логічний формат пакета з layout у RAM.
4. Ігнорують endianness.
5. Використовують packed-структури без оцінки впливу на продуктивність/вирівнювання.

---

## 12. Рекомендації

1. Починайте зі `struct`, коли є сумніви.
2. Використовуйте `union` тільки коли справді потрібна економія пам'яті або альтернативне представлення.
3. Для протоколів:
- фіксуйте типи (`uint8_t`, `uint16_t`, ...);
- робіть `static_assert(sizeof(...))`;
- явно описуйте порядок байтів.
4. Додавайте коментар, яке поле union активне.
5. Валідуйте межі і розміри на етапі компіляції.

---

## 13. Міні-порівняння

### struct

- Безпечніше
- Зрозуміліше
- Більше пам'яті

### union

- Компактніше
- Гнучко для low-level
- Більше шансів на помилки

---

## 14. Приклад для заняття (C++)

```cpp
#include <cstdint>
#include <iostream>

struct Packet {
    uint8_t cmd;
    uint8_t len;
    uint8_t data[4];
};

union U32Bytes {
    uint32_t value;
    uint8_t bytes[4];
};

int main() {
    Packet p{0x10, 4, {1, 2, 3, 4}};
    std::cout << "Packet len=" << static_cast<int>(p.len) << "\n";

    U32Bytes u{};
    u.value = 0x12345678u;
    std::cout << "First byte=" << static_cast<int>(u.bytes[0]) << "\n";

    return 0;
}
```

Пояснення:

- `Packet` показує звичайне групування полів (`struct`).
- `U32Bytes` показує одні й ті самі дані у різних формах (`union`).

---

## 15. Висновок

- `struct` це основний інструмент моделювання даних у C/C++.
- `union` це спеціалізований інструмент для компактного/альтернативного представлення пам'яті.
- Для embedded обидва важливі, але `union` потрібно застосовувати обережно і тільки там, де є чітка потреба.
